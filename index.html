Task Board flow — from learner signal to completed follow-up

The Task Board converts learner follow-up signals into a single prioritized daily queue. This guide makes the generation flow, ownership, real-time tasks, coordinator actions, Exotel outcomes, RNR handling, exclusions, escalations, and admin controls explicit.

01

Why the Task Board exists

Before

Coordinator had to manually inspect several places to find learners who needed follow-up.

  • Welcome call due
  • CCT follow-up
  • Attendance / Flexi inactivity
  • Placement follow-up
  • Missed calls & callbacks
→

With Task Board

Those signals are evaluated and converted into one ranked queue for the responsible coordinator.

  • One daily working queue
  • Urgent tasks surfaced first
  • Task-linked call outcomes
  • History stays attached to the task
  • Admin can oversee the full team
02

The complete lifecycle

Think of the system as six connected stages. Regular tasks enter through the nightly worker; selected urgent callbacks can enter in real time.

Nightly flowReal-time insertionCoordinator ownership
STEP 1

Sync learner state

SyncLearnerStates maps batch ownership and refreshes the learner state used by the board engine.

STEP 2

Evaluate triggers

The engine checks each learner against welcome, CCT, fortnightly, attendance, placement, Flexi and live-eval rules.

STEP 3

Create / update tasks

BuildCoordinator creates deterministic tasks with dedupe protection instead of producing duplicate cards.

STEP 4

Prioritize board

Tasks are distributed into Priority 1, Priority 2–3 and Over Cap, with top metric cards for quick load visibility.

STEP 5

Coordinator acts

Call, complete, reschedule, schedule callback, set preferred time, do-not-call, or escalate.

STEP 6

Outcome updates state

Exotel or a manual action updates the exact task, RNR state and follow-up clocks; admin handles escalated work.

PHASE A · 03:15 IST

SyncLearnerStates

Find the learners owned through each batch's mainCoordinator, then sync the learner state used for task evaluation. If ownership changes, the next sync is the point where open work can follow the new owner.

PHASE B · AFTER SYNC

BuildCoordinator

Evaluate deterministic trigger rules, dedupe existing tasks, construct the coordinator queue, calculate lane distribution and populate the top summary cards.

Missed nightly run? If the 03:15 run was missed because the app was down, CatchUpOnBoot can rebuild today's board when the worker boots.

05

All task triggers

Nine trigger categories feed the board. The first seven are regular proactive signals; the last two are callback-oriented and can be time-critical.

01

Welcome Call

New batch learner needs a welcome call within the first two working days.

02

CCT Push Call

CCT follow-up occurrences inside the 45-day window, including Day 12, 24, 35 and 45 pushes.

03

15-Day Fortnightly

Golden-rule proactive follow-up when there has been no proactive contact for 15 working days.

04

Attendance Inactivity

Mainboot learner is repeatedly absent and needs a follow-up call.

05

Placement Follow-Up

Learner is in pre-placement or main-placement follow-up scope.

06

Flexi Non-Engagement

Flexi learner has remained inactive without expected content engagement.

07

Live Evaluation Gap

A submitted project has remained without evaluation beyond the configured gap.

08

Learner-Requested Callback

Coordinator schedules a callback requested by the learner. Same-day callbacks can appear immediately.

09

Missed Inbound Callback

A learner's inbound call was missed and needs a same-day return call.

06

What the coordinator sees and does

A. Board lanes

Priority 1

Time-sensitive work that should be handled first.

  • Welcome window closing
  • Missed inbound callbacks
  • RNR retries
  • Same-day callback work

Priority 2–3

Due proactive work that is important but less urgent.

  • CCT push
  • 15-day follow-up
  • Flexi non-engagement
  • Placement follow-up
  • Live-eval gap

Over Cap

Work above today's effective calling capacity.

  • Preserved safely
  • Rolls over
  • History is not lost
Welcome dueCCT push15-day dueRNR / missedFlexi at-risk

B. Daily working flow

1

Scan top cards and Priority 1

Understand where the day's load is concentrated before opening individual tasks.

2

Search / filter the queue

Work by learner, batch, task type, RNR, priority or rollover category.

3

Open learner call detail

Review learner context, recent calls, CCT/RNR timing, activity and existing notes.

4

Call from Task Board

Click-to-call sends the task identity with the Exotel flow so the callback outcome can update the exact task.

5

Or take a manual action

Complete, Reschedule, Schedule Callback, or save a Preferred Call Window depending on what the learner needs.

6

Handle exceptions

Use Do Not Call to suppress contact, or Escalate when admin intervention is required.

C. Three coordinator tabs

Board

Today's working queue, including Priority 1, Priority 2–3 and Over Cap.

Excluded

Suppressed learners such as disableCall, on-hold or other excluded states. Do-not-call suppresses open tasks.

Escalated

Tasks handed to admin. They are locked/read-only for the coordinator until resolved or returned.

07

What happens after a call?

Connected

When the Task Board call connects and the Exotel outcome returns, the exact task can close automatically. The 15-day proactive clock resets and the RNR counter resets.

Call from Task Board→Exotel outcome→Task done→RNR = 0

No Answer / Busy

The failed attempt is recorded in the RNR flow. The next attempt can rotate to another slot; after repeated attempts the learner can move into cooldown.

No answer / busy→RNR +1→Slot rotation→3 attempts → cooldown

Manual completion: If the learner was contacted outside Task Board / Exotel (for example WhatsApp or personal phone), the coordinator can use Complete with a note. This was verified to mark the task done and reset the 15-day clock.

09

Coordinator leave & catch-up behavior

Coordinator availability changes board generation mode without deleting the existing backlog.

Active coordinator

isCallerActive = true. Normal proactive task generation and daily board work continue.

→

On Leave

isCallerActive = false. New proactive generation pauses, while already-open tasks and backlog remain preserved.

→

Active again

The board can move into catch-up behavior so preserved backlog is prioritized and worked down instead of being lost.

Separate from cron catch-up: CatchUpOnBoot handles a missed nightly board build; coordinator catch-up handles preserved work after leave.

Demo-ready Q&A

Q1. Exactly when is a task created?

Regular proactive tasks: daily 03:15 IST nightly worker build.

Real-time tasks: Missed Inbound Callback and same-day learner-requested callback do not wait for the night build.

Missed cron: CatchUpOnBoot can build today's missing board after the app starts again.

Q2. In which cases is a task created?

There are 9 trigger categories: Welcome Call, CCT Push, 15-Day Fortnightly, Attendance Inactivity, Placement Follow-Up, Flexi Non-Engagement, Live Evaluation Gap, Learner-Requested Callback, and Missed Inbound Callback.

Q3. Which coordinator’s board will a learner appear on?

Ownership is based on batches.mainCoordinator. Learners from the batches where a coordinator is the main coordinator form that coordinator's Task Board scope. users.callerHash is not the Task Board ownership source.

If the learner changes batch or the batch's main coordinator changes, the next sync realigns open work to the new owner.

Q4. What happens when a coordinator is on leave?

When isCallerActive = false, new proactive generation pauses. Existing open tasks and backlog are preserved. When the coordinator becomes active again, catch-up behavior helps prioritize the backlog.

Q5. Can duplicate tasks be created for the same learner?

Repeated builds are idempotent. Logical tasks use a deterministic dedupeKey, and open proactive work is deduped / preempted so the learner is not flooded with competing proactive cards.

welcome:<studentHash>cct:<studentHash>:<occurrence>fortnight:<studentHash>:<fortnightIdx>

Q6. What happens after a call is completed?

Connected: task closes, the 15-day proactive clock resets, and RNR resets.

No Answer / Busy: RNR increases, the next attempt can rotate to another slot, and repeated attempts can move the learner into cooldown.

Q7. Is the Task Board available for every Business Unit?

No. This flow is scoped to Zenclass-category programs. B2B / B2I are outside the supported Task Board flow and are blocked by the application's access rules.

Q8. Can a coordinator edit or complete another coordinator’s task?

No. Backend ownership validation is applied to task actions such as complete, reschedule, escalate, manual schedule and availability. Non-owner completion was explicitly verified as forbidden. Admins use taskBoard.adminview for team drill-down and escalation handling.
